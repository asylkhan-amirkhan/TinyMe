# Магазин: изменения и перенос на телефон

Добавлены корзина (количество 1–99, удаление, итог), избранное, поиск, категории и CRUD товаров. Управление каталогом доступно только администраторам. Покупки за виртуальные монеты сохраняют отдельные копии в инвентаре. Оплаты реальными деньгами нет.

## Состояние базы

В текущем TinyMe уже есть Supabase, миграции комнаты, кошелька, музыки и авторизации. Архив магазина подготовлен для другой базы Git (`cf0c282557bb72299f39da2381ad775c731b67f9`), поэтому заменять им общие файлы проекта нельзя. Новый магазин на `/shop` и `/inventory` использует отдельные таблицы `tinyme_*`, не меняя существующие таблицы. Его баланс, права администратора и покупки не связаны с балансом комнаты, мастерской и её инвентарём. Автоматического переноса нет. Удалённое подключение в ходе этой проверки не проверялось.

## Настройка

1. В существующем проекте Supabase выполните `supabase/migrations/202611180001_shop.sql` через SQL Editor (один раз) либо примените её привычным механизмом миграций Supabase.
2. Для новой установки скопируйте `.env.example` в `.env.local`; существующий файл не перезаписывайте. Укажите `NEXT_PUBLIC_SUPABASE_URL` и публичный `NEXT_PUBLIC_SUPABASE_ANON_KEY` либо `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (он имеет приоритет). **Service role / secret key в публичные переменные не подходит.** На Vercel добавьте эти же публичные настройки и пересоберите приложение. Комната сохраняет существующий режим `localOnly`; отдельный магазин подключается к аккаунту только на своих страницах.
3. Для входа нужен пользователь Supabase Auth с email и паролем. Для проверки можно создать подтверждённого пользователя через Dashboard → Authentication → Users. Регистрация и восстановление пароля не входят в эту задачу.
4. Назначьте администратора из SQL Editor, заменив UUID на ID пользователя:

```sql
insert into public.tinyme_admins(user_id)
values ('USER_UUID') on conflict do nothing;
```

5. Баланс нового пользователя в отдельном магазине — 0. Таймер комнаты не начисляет монеты в `tinyme_wallets`. Для проверки покупки выдайте тестовому аккаунту монеты из SQL Editor:

```sql
insert into public.tinyme_wallets(user_id, balance)
values ('USER_UUID', 100)
on conflict (user_id) do update set balance = excluded.balance;
```

6. Выполните `npm ci`, `npm run dev`, откройте `/shop` и войдите. Администратор увидит «Управление товарами». `/inventory` показывает покупки и бесплатный стартовый набор.

Пользователи не могут назначить себя администраторами, изменить баланс или вручную добавить покупку в инвентарь. RLS ограничивает персональные строки владельцем. Оформление покупки выполняется SQL-функцией: блокировка корзины, проверка текущих цен и наличия, списание, создание копий и очистка корзины в одной транзакции. При ошибке изменения откатываются. Купленная копия содержит снимок товара и переживает его удаление. Снятый с продажи товар можно убрать из корзины.

## Проверки

```bash
npx tsc --noEmit
npm run lint
npm run test:shop
npm run build
```

Тест БД запускает PostgreSQL в памяти через PGlite и подставляет минимальную схему Supabase Auth. Он проверяет RLS, права администратора, ограничения, покупку, недостаточный баланс, изменение цены, откат, повторное оформление и сохранность купленных копий. Это не проверка настоящего Supabase Auth, сетевых запросов, конкурентных транзакций или Vercel.

Результат проверки 18.11.2026: TypeScript, ESLint и тест БД прошли. Повторная production-сборка завершилась с кодом 0, страницы `/shop` и `/inventory` отвечают HTTP 200. Next.js сообщает об известной уязвимости установленной версии 16.4.2 и рекомендует обновление; первый запуск сборки остановился на этом уведомлении, повторный продолжился с предупреждением. Обновление фреймворка в эту задачу не включено. Визуальная проверка не выполнена: браузерный инструмент недоступен. Реальное подключение Supabase и вход проверить без конфигурации нельзя.

После подключения проверьте двумя аккаунтами: добавить/убрать избранное, поменять количество и перезагрузить; купить и открыть инвентарь; проверить чужой аккаунт; администратором создать/изменить/удалить товар. Существующие комната, таймер и мастерская сохраняют свою реализацию, но покупки отдельного магазина в них не появляются.

## Отправка на телефон и коммит

В корне проекта выполните:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/export-shop.ps1
```

В `transfer/` появится `TinyMe-shop-ДАТА-ВРЕМЯ.zip`. Отправьте этот ZIP себе на телефон. Внутри:

- `files/` — полные версии новых и изменённых файлов с исходными путями, включая скрытый `.env.example`;
- `CHANGED-FILES.txt` — список файлов и исходный commit;
- `TinyMe-shop.patch` — полный патч, включая новые файлы.

Если работаете через редактор репозитория на телефоне, перенесите содержимое `files/` в репозиторий с сохранением путей и создайте один коммит. Для Git-клиента с терминалом используйте патч на той же базовой версии:

```bash
git apply --check TinyMe-shop.patch
git apply TinyMe-shop.patch
git status --short
git add .gitignore .env.example package.json package-lock.json app features/shop lib/supabase.ts supabase/migrations/202611180001_shop.sql tests/shop-database.mjs scripts/export-shop.ps1 docs/shop-changes.md docs/week-plan.md README.md
git commit -m "feat: add Supabase shop, cart, favorites and product CRUD"
git push
```

Выберите перенос файлов или применение патча, не оба сразу. Архив не содержит `.env.local`, паролей, `node_modules`, `.next` и пользовательской БД. Перед коммитом просмотрите изменения. Скрипт экспорта не меняет настоящий Git index и не создаёт коммит.

Основа интеграции: [Supabase JS](https://supabase.com/docs/reference/javascript/initializing), [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security).
