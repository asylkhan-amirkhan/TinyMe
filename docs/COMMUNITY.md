# Сообщество TinyMe

Социальные функции доступны из магазина комнаты по ссылке «Сообщество и подборки» и из каждой карточки по ссылке «Отзывы и обсуждение».

| Адрес | Возможности |
| --- | --- |
| `/catalog` | Вещи из основного каталога и локальной мастерской; поиск, категории, цена, рейтинг и сортировка |
| `/catalog/[id]` | Описание вещи, средняя оценка, отзывы, комментарии, полезные отзывы (лайки), добавление в свою подборку |
| `/community` | Опубликованные подборки и профили |
| `/profiles/[id]` | Профиль, отзывы и подборки автора; редактирование собственных данных |
| `/collections/[id]` | Отдельная страница подборки с адресом для публикации |

## Локальный режим

По умолчанию используется существующий локальный вход TinyMe. Новая информация хранится в `tinyme:community:v1`, отдельно от комнаты, музыки и аккаунтов. Пароли и email в публичные профили не копируются. Профили и подборки изначально скрыты; публикация включается автором. Корзина и избранное подготовлены в модели хранения, интерфейс комнаты продолжает использовать прежний магазин.

«Публично» в этом режиме означает доступность другим аккаунтам **того же браузера**. Другой ноутбук или браузер этих данных не увидит. Это локальный прототип, его проверки прав не заменяют серверную авторизацию.

Отзывы можно редактировать, один пользователь оставляет один отзыв на товар. Лайки не дублируются. Удаление отзыва удаляет его комментарии и лайки. Пользователь может удалять только собственные отзывы, комментарии и подборки. Архивирование товара не удаляет историю отзывов. Запись между вкладками сериализуется Web Locks API, если браузер его поддерживает.

## Общая база MyRoom

Код подключения к Supabase подготовлен, но требует доступной базы и применения схемы. Он не включается автоматически при наличии ключей, чтобы не переносить локальные данные без явного решения.

1. Проверить текущую схему существующего проекта MyRoom. `supabase/community.sql` — подготовленный SQL для **однократного** применения через новую миграцию, а не автоматически выполненная миграция. Скрипт расширяет существующую `catalog_items`, добавляет социальные таблицы и RLS. Комнату, музыку и кошелёк он не удаляет.
2. Применить SQL через штатный процесс миграций проекта, затем `supabase/community-catalog-backfill.sql` для категорий и иллюстраций существующих товаров. Выполнить проверки RLS под разными пользователями. Основной SQL не применять повторно: имена таблиц, ограничений и политик фиксированы.
3. Указать `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` (подходит публичный publishable key) и установить `NEXT_PUBLIC_COMMUNITY_MODE=cloud`. Перезапустить приложение.
4. Войти или зарегистрироваться один раз через /login или /register. Комната и сообщество используют одну сессию Supabase Auth. Локальные аккаунты не являются Supabase Auth пользователями и автоматически туда не переносятся. При включённом подтверждении email сначала подтвердить письмо.

Общий каталог использует `catalog_items`; отзывы, комментарии и подборки ссылаются на его идентификаторы. Профили привязаны к `auth.users`. Закрытые профили/подборки читаются только владельцем, корзина и избранное — только своим пользователем. Публичные отзывы, комментарии, лайки и опубликованные подборки доступны для чтения всем.

Роль администратора общей базы задаётся только доверенным сервером в `app_metadata.role`. Выбор администратора в локальной регистрации **не даёт** прав на изменение общей базы. Привилегированные ключи в браузере не используются. Запись подборки и её состава выполняется в одной транзакции через invoker RPC с политиками владельца.

После подключения проверить создание и повторное открытие профиля, отзыв с другого аккаунта, повторный лайк, изменение чужого отзыва (должно быть запрещено), закрытую подборку из анонимной сессии (должна быть скрыта), публикацию и удаление подборки. Сборка/TypeScript и локальные тесты не подтверждают работоспособность недоступной удалённой базы.
